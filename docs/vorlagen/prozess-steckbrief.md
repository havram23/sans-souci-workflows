# Prozess-Steckbrief

Ausfüllbare Arbeitsvorlage. Keine Personen- oder Zugangsdaten in ein öffentliches Repository eintragen.

| Frage | Eigene Antwort |
| --- | --- |
| Welcher konkrete Vorgang soll vereinfacht werden? | |
| Wer ist fachlich verantwortlich? | |
| Was löst den Vorgang aus? | |
| Welche Quelldaten und Formate werden benötigt? | |
| Welche Ausgabe gilt als richtig? | |
| Wo wird menschliche Freigabe benötigt? | |
| Wie oft läuft der Vorgang, mit welchem Volumen? | |
| Welche Ausnahmen kommen tatsächlich vor? | |
| Welche Berechtigungen sind nötig? | |
| Wie erkennt man fehlende oder doppelte Vorgänge? | |
| Was geschieht bei Ausfall eines Zielsystems? | |
| Wer erhält einen Vorfall, wer darf ihn abschließen? | |
| Wann werden Daten gelöscht oder archiviert? | |
| Wie erfolgt Rücknahme bzw. manueller Ersatz? | |

## Nutzen messen

Zeit pro Vorgang vor Einführung: ___ Minuten. Anzahl pro Monat: ___. Verbleibende manuelle Zeit: ___ Minuten. Laufende Toolkosten: ___. Monatliche Betreuung: ___. Einmalige Einführung: ___.

Gesparte Stunden = Anzahl × (Zeit vorher − Zeit nachher) / 60. Daraus folgt erst dann eine finanzielle Ersparnis, wenn die frei gewordene Kapazität tatsächlich nutzbar wird. Fehlerkosten, Ausnahmen und Pflegeaufwand gesondert erfassen.

## Abnahme anhand von Beispielen

Mindestens einen normalen Vorgang, eine fehlende Pflichtangabe, einen doppelten Eingang, eine abgelehnte Freigabe und einen Zielsystem-Ausfall mit synthetischen Daten prüfen. Erwartetes und beobachtetes Ergebnis dokumentieren.
